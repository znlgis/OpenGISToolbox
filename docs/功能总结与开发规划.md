# OpenGIS Toolbox 功能总结分析与开发规划

> 基准版本：main@6384e50（2026-09-15「全面真实数据测试与工具缺陷修复」）
> 规划侧重：**功能扩展** ｜ 时间跨度：**约 2 个月（4 个 Sprint，每 Sprint 2 周）** ｜ 日期：2026-09-24

---

## 一、项目定位与功能全景

**OpenGIS Toolbox** 是基于 .NET 10 + Avalonia UI 11.3 的开源跨平台桌面 GIS 工具箱（对标 NextGIS Toolbox），以自研引擎 [OpenGIS.Utils (OGU)](https://github.com/znlgis/opengis-utils-for-net) 1.0.8（GDAL/MaxRev 内核）为处理核心，采用 CommunityToolkit.Mvvm + Template Method（ToolBase）架构。

### 1.1 功能盘点（已注册 42 个工具，10 大类）

| 类别 | 工具数 | 内容 | 实现层 |
|------|--------|------|--------|
| 格式转换 | 12 | SHP/GeoJSON/GPKG/KML/DXF/FileGDB 互转、CSV→矢量、PostGIS 导入/导出 | 引擎 ConvertFormat + 应用层 PostGIS 预处理 |
| 几何处理 | 13 | Buffer、Union、Intersection、Difference、ConvexHull、Centroid、Simplify、CentralLines、Fix/Merge/Split/Clip/SpatialJoin | 引擎 GeometryUtil（GEOS 路线） |
| 几何验证 | 1 | CheckGeometry（详细错误报告） | 引擎 TopologyValidation |
| 坐标转换 | 2 | Reproject、批量 Reproject | 引擎 CrsUtil |
| 空间分析 | 4 | 面积、长度、空间过滤、属性查询 | 应用层 + 引擎 |
| 栅格 | 2 | 栅格格式转换、栅格计算器（NDVI/Scale/Offset/Threshold） | 直接绑定 OSGeo.GDAL |
| 遥感 | 1 | 卫星影像瓦片下载（Sentinel-2/Landsat） | HTTP |
| GPS | 1 | GPX 提取航点/轨迹/摘要 | 应用层 |
| 地理编码 | 1 | Nominatim 地址编码 | HTTP |
| 实用工具 | 2 | ZIP 压缩/解压 | 引擎 ZipUtil |

### 1.2 质量保障体系（项目当前最厚实的资产）

- **三轨测试**：`tests/OpenGISToolbox.TestKit`（GDAL 环境卫生 + 无 UI 调工具 + SHP/DBF/GeoJSON 独立二进制解析器）、`tests/OpenGISToolbox.Tests`（xUnit 61 用例，10 个测试类）、`tools/OpenGISToolbox.RealDataHarness`（控制台全工具遍历，9 个 Section，185 项检查，Fail 退出码 1 可接 CI）。
- **数据无关设计**：数据目录/PG 连接/联网开关全部经 `OGT_*` 环境变量注入，期望值从数据文件头独立推导做交叉校验，缺数据自动跳过——新工具可低成本接入同一验证范式。
- **真实数据驱动修复闭环**：本轮测试发现并修复 7 项缺陷（2 项引擎层随 1.0.1→1.0.8 升级解决；5 项应用层落地：headless 缺省值、NullShape 剔除、PostGIS 多重几何列升位、numeric 溢出扩位、DXF 多部件拆分）。
- **国际化**：zh/en 双语（LanguageManager + axaml 资源字典），工具中英文元数据齐全。

### 1.3 近期演进脉络

```
优化代码 → 中英切换 → 拆分优化工具实现(ToolBase 模板方法化) → 优化UI交互
→ 真实数据测试 + 系统GDAL冲突修复 → 全面真实数据测试与工具缺陷修复(HEAD)
```

项目已从「快速堆功能」阶段切换到「架构化 + 真实数据验证」阶段，具备系统性扩功能的条件。

## 二、现状分析：优势、短板与差距

### 2.1 优势

1. **加工具成本极低**：ToolBase 模板方法统一计时/错误处理/进度/参数校验，新工具只需 `BuildParameters + ExecuteCoreAsync` + ToolRegistry 注册一行，UI 自动呈现；标准参数类型零视图改动。
2. **引擎自主可控**：OGU 为自研库，应用层遇到引擎缺口可下发到引擎侧修（本轮 DXF/FileGDB 缺陷即此路径），不受第三方库节奏约束。
3. **测试资产可直接复用**：新增任何工具都能套「合成数据已知值断言 + 真实数据独立推导交叉校验 + harness ErrorMatrix 优雅失败」三件套。

### 2.2 短板与缺口（对标 NextGIS Toolbox / QGIS Processing）

| 领域 | 缺口 | 影响 |
|------|------|------|
| **几何处理** | 无 Dissolve（按属性融合）——最高频工具之一；无 Multipart↔Singlepart 互转；无提取顶点/边界/线转面；SymDifference 引擎已支持但未工具化 | 与 NextGIS「矢量地理处理」全集相比缺核心件 |
| **空间分析** | 无按位置提取（Extract by location）、最近邻/距离矩阵、点在多边形计数、渔网网格生成 | 分析类只有 4 个工具，深度不足 |
| **栅格** | 仅 2 个工具；缺 DEM 地形分析（坡度/坡向/山体阴影/等高线）、重投影/裁剪/镶嵌、分区统计 | 栅格侧明显薄弱（GDAL 全能力只用了零头） |
| **高级几何** | Voronoi/Delaunay：引擎 GeometryUtil 无此 API，需引擎层新增 | 泰森多边形是常见插值/分区前置 |
| **批量能力** | 全部工具为单文件输入，无目录级批量转换 | 实用性瓶颈，用户真实数据常为成批 shp |
| **工程化** | 无 GitHub Actions workflow（run-tests.sh 已具备 CI 接口却未接）；无发布安装包/版本 tag | 开源项目成熟度欠缺 |

### 2.3 引擎能力面核查（规划可行性依据）

对 OGU 1.0.8 程序集反射确认：

- **应用层可直接用**（无需引擎改动）：`GeometryUtil` 的 Buffer/Union/Intersection/Difference/**SymDifference**/ConvexHull/Centroid/Simplify/**Densify**/**Boundary**/Envelope/Distance/全套谓词（Contains/Within/Intersects/Touches/Crosses/Overlaps/Disjoint/IsWithinDistance）；`OguLayerUtil.Read/Write/ConvertFormat`（含 Async）；`PostgisUtil`；`CrsUtil.Transform`；栅格工具可继续直接绑定 OSGeo.GDAL（RasterFormatConvertTool 已开此先例）。
- **需引擎层新增**：Voronoi/Delaunay（GeometryUtil 无对应方法）；栅格 DEM 系列若走 `GdalCmdUtil` 需确认 MaxRev 绑定暴露度（备选：直接 Gdal API 或 gdal 命令行）。

## 三、功能规划（4 个 Sprint，约 8 周）

> 原则：① 优先「应用层即可实现 + 用户高频」的工具，引擎层改动集中安排；② 每个新工具同步落 xUnit 合成数据用例 + harness Section 检查（延续数据无关、独立推导期望值范式）；③ 中英文元数据与 README 同步更新。

### Sprint 1（第 1–2 周）：矢量几何高频补全 ⭐ 最高性价比

| # | 任务 | 实现层 | 验收标准 |
|---|------|--------|----------|
| 1.1 | **Dissolve 按属性融合**：选分组字段→组内 Union 折叠（复用 Buffer 双策略折叠经验：批量 Boolean 分批折叠 + 面积守恒门控） | 应用层（GeometryUtil.Union） | 真实国家层按属性分组：输出要素数 == 分组数；输出面积 == Σ(组内面积)；输出几何 IsValid |
| 1.2 | **Multipart→Singlepart / Singlepart→Multipart** 互转 | 应用层 | Split 分片求和回归模式复用：拆分后 Σ 要素数 == 部件总数；合并后往返守恒 |
| 1.3 | **几何派生工具组**：提取顶点（Extract vertices）、多边形边界→线（GeometryUtil.Boundary）、线→多边形 | 应用层 | 顶点数守恒（Σ 输出点数 == NumPoints 总和）；线转面后面积 == Shoelace 独立计算值 |
| 1.4 | **批量输入参数类型**：`ParameterType.InputDirectory`/多文件 + **目录批量格式转换**（递归发现成对 shp/dbf 的逻辑可从 TestKit RealDataCatalog 移植） | 应用层（Models/ToolParameter + ToolExecutionView） | harness 新 Section「批量转换」：目录内 N 个图层逐一转换，逐层要素数保真；UI 可多选 |
| 1.5 | **SymDifference 工具化**（引擎已有，仅注册） | 应用层 | AΔB == (A−B)∪(B−A) 面积恒等式断言 |

### Sprint 2（第 3–4 周）：空间分析深化

| # | 任务 | 实现层 | 验收标准 |
|---|------|--------|----------|
| 2.1 | **按位置提取 Extract by location**：输入层 + 参考层 + 谓词下拉（intersects/contains/within/distance≤） | 应用层（GeometryUtil 谓词） | 期望子集由独立解析器二次计算交叉比对；空结果优雅成功 |
| 2.2 | **最近邻连接 KNN / 距离矩阵**：应用层网格索引（8r 网格 + 并查集的思路可复用），输入点层 + 目标层 → 最近目标及距离字段 | 应用层 | 合成数据已知最近邻断言；真实数据距离 == 引擎 Distance 逐对抽样复核 |
| 2.3 | **点在多边形计数 Count points in polygon**：多边形层新增计数字段 | 应用层 | Σ 计数 == 点总数（无投影容差场景） |
| 2.4 | **创建渔网网格 Create Grid**：范围 + 行列/像元尺寸 → 面网格（附编号字段） | 应用层 | 行×列 == 要素数；总面积 == 范围面积 |

### Sprint 3（第 5–6 周）：栅格专题

| # | 任务 | 实现层 | 验收标准 |
|---|------|--------|----------|
| 3.1 | **DEM 地形分析**：坡度/坡向/山体阴影（Gdal.DEMProcessing 绑定或 gdal 命令行，选型先做 1 天 spike 验证 MaxRev 暴露度） | 应用层直连 GDAL | 合成斜坡 DEM：坡度≈设计角 ±0.5°、坡向象限正确；山体阴影值域 [0,255] |
| 3.2 | **等高线提取**：DEM→间隔可配的等值线矢量 | 应用层直连 GDAL | 等值线数量 == (max−min)/间隔；线几何 IsValid |
| 3.3 | **栅格重投影 Warp + 裁剪 + 镶像 Mosaic** | 应用层直连 GDAL | 重投影后像元中心经 CrsUtil.Transform 反算落回原像元；镶嵌后范围 == 各输入范围并集 |
| 3.4 | **分区统计 Zonal Statistics**：矢量面 × 栅格 → 每面统计 mean/min/max/count | 应用层 | 合成常量栅格：每面 mean == 常量、count == 面内像元独立计算值 |

### Sprint 4（第 7–8 周）：高级几何 + 工程收尾发布

| # | 任务 | 实现层 | 验收标准 |
|---|------|--------|----------|
| 4.1 | **Voronoi（泰森多边形）+ Delaunay 三角网**：OGU 引擎 GeometryUtil 新增 API（**注意**：开放区域裁剪不能直接塞整个 bbox——GeoPipeAgent 项目实测胞元重叠 12.6 倍的教训，须用 shapely voronoi_diagram + 回配点等效方案），发 OGU 新版本后应用侧包装工具 | **引擎层 + 应用层** | 合成点集：每点恰落入自己胞元（Contains 断言）；胞元面积和 == 裁剪框面积；Delaunay 三角面积和 == 凸包面积 |
| 4.2 | **CI 接入**：GitHub Actions（windows-latest）跑 `run-tests.sh`（xUnit 全量 + 缺数据自动跳过策略），PR/push 触发 | 工程层 | 连续绿；harness 模式可选手动触发（避免 Natural Earth 下载拖慢每次 CI） |
| 4.3 | **v1.1.0 发布**：三大平台构建产物（zip 免安装包起步）、CHANGELOG、README 双语工具表同步到 42+新增 | 工程层 | GitHub Release 附件可下载运行；README 工具计数与 ToolRegistry 断言（SmokeTests 已有 ID 唯一性检查，可加 README 表数一致性用例） |

### Backlog（2 个月后候选，不在本期内）

- 网络分析（最短路径/服务区，需引擎层图数据结构，工作量≈独立 Sprint）
- 执行历史 / 输出文件管理 / 工具搜索（体验类）
- 更多格式：DGN、MapInfo TAB、Excel/ODS 读写、GeoParquet
- 插件式工具加载（Assembly 扫描或脚本接口）
- 内存缓存与超大图层流式处理（>10 万要素性能专项）

## 四、里程碑与依赖

```
W1-2  Sprint1 矢量高频      → 里程碑 M1：Dissolve 等高频缺口补齐（约 +6 工具）
W3-4  Sprint2 空间分析      → 里程碑 M2：分析类 4→8 工具
W5-6  Sprint3 栅格专题      → 里程碑 M3：栅格类 2→7 工具（依赖 3.1 选型 spike 结果）
W7-8  Sprint4 高级+发布     → 里程碑 M4：v1.1.0 发布（依赖 OGU Voronoi 版本发布）
```

关键依赖与风险：

1. **OGU 发版节奏**（Sprint 4 Voronoi）：引擎新增 API → 发 NuGet → 应用升级引用，预留 1 周缓冲；若延期，Voronoi 降级为 Backlog，v1.1.0 不受阻塞。
2. **GDAL DEM 绑定能力**（Sprint 3 第一天做 spike）：若 `Gdal.DEMProcessing` 不可用，回退 gdal 命令行方案（GdalCmdUtil 路线），需处理 PATH 中 OSGeo4W 冲突（已有 TestKit GdalEnv 成熟处理可复用）。
3. **Dissolve 大数据性能**：重度自交多边形折叠已有 Buffer 双策略经验，面积守恒门控直接移植；真实国界级数据作为验收上限。
4. **批量转换与现有单文件工具的关系**：作为参数类型扩展而非新工具，避免工具数膨胀、复用全部既有执行逻辑。

## 五、与现有测试体系的衔接约定

每个新工具落地时同步交付（沿用 0915 轮确立的模式）：

1. **xUnit 合成数据用例**：TestEnv/Synth 运行时生成已知值断言，加入对应测试类（几何→GeometryToolTests、栅格→RasterTests、批量→新 BatchTests）；
2. **harness Section 检查**：真实数据独立推导期望（文件头/独立解析器交叉校验），计入 Pass/Warn/Fail 与 CI 退出码；
3. **ErrorMatrix 自动纳入**：全注册工具的缺参/坏文件/非法参数优雅失败矩阵自动覆盖新工具（注册即可得）；
4. **i18n**：Name/NameZh/Description/DescriptionZh 四件套 + Lang 资源补齐，SmokeTests 的注册完整性检查自动校验。
